`implemented` is the only status that promises anything. The other three tell a
reader to expect nothing, so getting them wrong is embarrassing; getting this one
wrong sends someone to write code against something that is not there. Two false
`implemented` claims have already shipped on this site — a ⌘K assistant that never
existed, and a Copy-for-AI button that did not either — and both were caught by a
person looking, which neither scales nor lasts.

The audit has two halves, and the second is the one that closes the class:

1. Every claim that has a verifier gets measured.
2. **Every claim must have a verifier.** A new `implemented` badge on something

Endpoints behind auth are no longer taken on trust: the audit generates a root
key, issues itself a DeviceCredential, signs the login challenge and calls them
with a real session — the same flow a new developer runs, with no signup.
