Downloading a binary from us means trusting us. This page is how you check instead.

## The command

Release artifacts in
[`LibertyNetHQ/libertynet-releases`](https://github.com/LibertyNetHQ/libertynet-releases/releases)
are signed with **cosign keyless** (Sigstore + GitHub OIDC). There is no long-lived private
key on our side, and **no public key for you to fetch** — the trust root is the public
Sigstore transparency log.

You need only [cosign](https://docs.sigstore.dev/cosign/system_config/installation/) v2+:

```bash
cosign verify-blob \
  --bundle "<artifact>.sigstore.json" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  --certificate-identity-regexp '^https://github\.com/LibertyNetHQ/libertynet-releases/\.github/workflows/sign-release\.yml@refs/' \
  "<artifact>"
```

`Verified OK` is a pass.

<Warning>
**Do not drop the two `--certificate-*` flags.** A signature that verifies without them
proves only that *somebody* signed. Those flags are what pin the signer to
**this repository's `sign-release.yml` workflow**, issued by GitHub's OIDC provider.
That pinning is the entire security property.
</Warning>

The identity is matched by regex rather than exactly because the certificate's subject ends
in the git ref that triggered the run (`@refs/tags/<tag>` on a release, `@refs/heads/main`
on a manual re-sign). The pattern pins repository and workflow file; only the ref floats.

Each artifact ships three files. `<artifact>.sigstore.json` is the bundle used above;
`<artifact>.sig` and `<artifact>.pem` are the raw signature and the short-lived certificate,
for older tooling or if you want to inspect the subject yourself.

## What this proves — and what it does not

**Proves**

- The file was signed by the `sign-release.yml` workflow in `LibertyNetHQ/libertynet-releases`.
- It has not been altered by one byte since. A poisoned mirror, a swapped GitHub asset, or a
  man-in-the-middle all fail verification.
- The signing event is in the **Rekor public transparency log** — independently auditable,
  and not removable by us afterwards.

**Does not prove**

- ❌ **That the binary was built from any particular source commit.** Build provenance (SLSA)
  would have to be produced inside the private build repository; it is *planned, not done*.
  The commit SHA in release notes is currently **not externally verifiable** — you are taking
  our word for that one.
- ❌ That the code is free of bugs or behaves safely. Signatures cover origin and integrity, nothing else.
- ❌ Anything about Apple. The macOS `.pkg` is still unsigned and un-notarized, so Gatekeeper
  will still object and still needs right-click → Open. An Apple Developer account is planned.

## The `ln-node` installer is a different line

`curl -sSL https://libertynet.ai/install.sh | bash` installs `ln-node`, whose artifacts come
from a **separate** release line, not the repository above.

| Protection | Status |
|---|---|
| SHA256 checksum | ✅ Enforced **fail-closed** — a missing, malformed, or mismatched checksum aborts the install with a non-zero exit. There is no skip switch. |
| cosign signature | ❌ Not yet. The signing workflow can only live in a public repository, and `ln-node` is built in a private one. |

<Warning>
Being straight about the limit: that checksum travels over the same channel as the binary. It
defends against corruption and against an attacker deleting the checksum file to bypass the
check — it does **not** defend against an attacker who replaces the binary *and* the checksum
together. Until this line is signed too, it is weaker than the one above.
</Warning>

## We run this check ourselves, daily

`verify-release.yml` in the releases repository re-runs exactly the command on this page from
a clean runner every day, **as an outsider** — no repository checkout, no secrets, anonymous
download — plus a negative case asserting that a tampered file *fails*. If that job goes red,
the promise on this page is false, and it says so publicly.

Full detail: [docs/VERIFYING.md](https://github.com/LibertyNetHQ/libertynet-releases/blob/main/docs/VERIFYING.md).
