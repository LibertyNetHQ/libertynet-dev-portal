<Warning>
**This site has no built-in "Ask AI" chat box.** <Status level="planned" />

An earlier version of this page described one, with a ⌘K shortcut. That was wrong: the chat
widget belonged to a hosted documentation platform this site does not use, and the page was
written before that decision was made. Nobody could ever have pressed ⌘K and got an answer.

It is corrected here rather than quietly deleted, because a portal whose whole argument is
"we never describe something as more finished than it is" should say so when it slips.
</Warning>

A hosted assistant needs an LLM API key on a server, which means a bill and a secret. That
is a decision for whoever pays it, not a default. So instead of a chat box, this site is
built to make **the assistant you already have** good at LibertyNet.

That is arguably the better trade anyway: your assistant keeps your context, your history
and your editor.

## Why the corpus matters more than the chat box

An assistant is a mirror of what it reads. The most useful thing this project can do for
AI-assisted development is not to bolt a model onto the docs — it is to leave nothing in the
docs for a model to be confidently wrong about.

Concretely, when you ask any assistant to write LibertyNet code:

- It cannot learn from this corpus that credits work, because no page says they do.
- It cannot learn that there is a wallet, because every page that mentions one says there
  is not.
- If it writes `ln.operator.settledCredits()` anyway, the SDK raises a typed error naming
  the real status rather than returning a plausible zero.
- With the [MCP server](/ai/mcp) it can call `capability_status` and simply look, instead of
  inferring from a page title.

Four independent layers, and not one of them is a chat box.

  <Accordion title="Give it the MCP server">

  </Accordion>

  <Accordion title="Or just paste the context">
    Use the **Copy for AI** button on any page, or take the whole corpus:

    ```bash
    curl -s https://docs.libertynet.ai/llms-full.txt
    ```

    Works with any assistant, including ones with no tool access at all.
  </Accordion>

  <Accordion title="Ask what is real before asking how">
    "Is X built?" is a cheap question with a definitive answer, and it saves you from a
    beautifully written implementation of something that does not exist. The
    [capability matrix](/status) is the whole answer in one file.
  </Accordion>

  <Accordion title="Paste the whole error">
    Every SDK error carries a stable `code` and a link to its entry in the
    [error dictionary](/reference/errors):

    ```text
    NotYetWiredError [NOT_YET_WIRED]: ... → https://docs.libertynet.ai/status
    ```

    That link is often all an assistant needs.
  </Accordion>
</AccordionGroup>

## The facts assistants most often get wrong

If you are prompting a model without tool access, these are the load-bearing ones. They are
also in [`llms.txt`](/ai/context), so it can read them itself.

```text
· LibertyNet has NO wallet, transfer, swap, staking, DEX or trading.
· Credits are a TEST UNIT and are not currently being counted at all.
· Discovery is public — there is no API key. Code that asks the user for one is wrong.
· "status": "active" does NOT mean online. Only last_seen decays.
· Most nodes are NOT reachable by you — filter with ?callable=1.
· A valid signature is NOT a valid identity. Verify id-binding FIRST.
· The same key appears as short did:svrp:n:<8hex> and full did:svrp:<64hex>.
· Public keys arrive as hex (/nodes) and base58 (/peers).
```

These are checked in CI. `tools/check-ai-answers.mjs` runs a set of golden questions —
including adversarial ones like *"write me code to transfer credits"* — against the same
tools and corpus an assistant would use, and fails the build if the honest answer is no
longer reachable.
